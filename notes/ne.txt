=== ne.py, both invocations, because the difference IS the finding

The pre-briefing reported `ne.py refuses cleanly and says why:
no NE signature at e_lfanew=256 (found b'PE')`. That is true when
the tool is handed a FILE. It was not true of the invocation this
session first ran, which handed it the tree, and the note that was
published under this name held only the traceback. See docs/14,
correction 27.

--- pointed at a FILE, which is what it wants: a clean refusal that
--- names both the offset and the signature it found instead
$ python tools/ne.py rpgmaker2003-steam/rpg2003.exe
  rpgmaker2003-steam/rpg2003.exe: no NE signature at e_lfanew=256 (found b'PE')
  exit=1
$ python tools/ne.py rpgmaker2003-steam/rpg_rt.exe.dat
  rpgmaker2003-steam/rpg_rt.exe.dat: no NE signature at e_lfanew=256 (found b'PE')
  exit=1
$ python tools/ne.py rpgmaker2003-steam/setup.exe.dat
  rpgmaker2003-steam/setup.exe.dat: no NE signature at e_lfanew=256 (found b'PE')
  exit=1
$ python tools/ne.py rpgmaker2003-steam/ultimate_eb.dll
  rpgmaker2003-steam/ultimate_eb.dll: no NE signature at e_lfanew=128 (found b'PE')
  exit=1
$ python tools/ne.py rpgmaker2003-steam/UNLHA32.DLL
  rpgmaker2003-steam/UNLHA32.DLL: no NE signature at e_lfanew=128 (found b'PE')
  exit=1
